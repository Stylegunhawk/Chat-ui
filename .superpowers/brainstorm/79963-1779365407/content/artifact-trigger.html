How does an artifact get created?

The trigger mechanism affects how the LLM produces artifacts and how much backend work is needed.

🤖 Assistant message

Code Block Upgrade

The LLM writes a normal ```html or ```mermaid block. A "▶ Preview" button appears on hover. No new tools needed — works with any model.

Pros

  • Zero backend change
  • Works with any LLM
  • Markdown-native

Cons

  • LLM doesn't "know" it's an artifact
  • No structured metadata
🤖 Assistant — calling tool
⚙ generate_artifact
type: "text/html" · title: "Dashboard"

Artifact ready → panel auto-opens
title · type · version tracked
Panel opens instantly, no user click needed

Dedicated Tool (generate_artifact)

LLM explicitly calls a generate_artifact MCP tool. Panel opens automatically. Artifact has structured metadata: title, type, version.

Pros

  • LLM is intentional
  • Typed + versioned
  • Auto-opens panel

Cons

  • Needs MCP tool wiring
  • Model must learn new tool
Smart models → tool path
⚙ generate_artifact → auto-open panel
— or —
Any model → code block path
```html → ▶ Preview button

Both (Recommended)

Code blocks get a "▶ Preview" button automatically. Smart models can also call generate_artifact for auto-open + metadata. Best of both worlds, progressive enhancement.

Pros

  • Works with any model
  • Smart models get full power
  • Backwards compatible

Cons

  • Two code paths to maintain
